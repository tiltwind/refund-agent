## 二、两层的关系

法规层是**底线**，平台层是**承诺**。

- 平台政策低于法定标准的，相应条款无效，以法规为准；
- 平台政策高于法定标准的（如金牌会员 15 天无理由退货），构成有效承诺，平台须履行；
- 平台层各文件相互冲突时，以 P02 为准，其余文件只作补充，不作减损。

答复消费者时应引用**平台层**条款——那是与消费者之间的直接约定；法规层用于判断平台条款是否有效、消费者是否另有法定救济途径。

## 三、元数据字段

每篇文档的 frontmatter 携带统一字段，供检索过滤使用：

| 字段 | 说明 |
|---|---|
| `doc_id` | 文档编号（L 开头为法规，P 开头为平台政策） |
| `title` | 文档全称 |
| `category` / `layer` | 分类与所属层（法律法规 `law` / 平台政策 `platform`） |
| `authority` / `publisher` | 发布机关或发布主体 |
| `doc_type` | 法律 / 行政法规 / 部门规章 / 平台服务协议 / 平台交易规则 |
| `effective_date` | 生效日期 |
| `expire_date` | 失效日期，长期有效记为 `9999-12-31` |
| `version` / `revision` | 版本号或修订信息 |
| `public_notice_date` | 平台层公示日期（规则变更须在实施前至少 7 日公示） |
| `authority_level` | 效力位阶：1 法律，2 行政法规与部门规章，3 平台规则 |
| `retrieval_scope` | 本文档回答哪一类问题 |
| `tags` | 主题标签 |

## 四、检索索引建议

### 4.1 切片粒度

每篇文档已按「条」组织，**一个 `###` 标题对应一条完整规则**，可直接作为一个检索单元。切片时保留标题作为该片段的 section 名，正文控制在 1000 汉字以内。

表格类条款（如 P02 第六条的审核顺序表、P06 第一条的运费归属表）须**整表作为一个片段**，不可从中间截断——半张表会给出与完整规则相反的结论。

### 4.2 必要的过滤字段

- `effective_date` / `expire_date`：用于排除尚未生效或已废止的版本。已生效订单适用下单时的规则版本，因此这两个字段必须参与过滤，不能指望从检索结果中事后辨别哪条还有效。
- `authority_level`：法规与平台规则冲突时用于定序。
- `layer`：答复消费者优先召回平台层，判断条款效力时召回法规层。

### 4.3 版本管理

政策改版时**新增版本而不是原地覆盖**：将旧版本的 `expire_date` 置为改版日期，新版本以新的 `effective_date` 入库。旧版本保留可查，用于处理改版前的存量订单。
