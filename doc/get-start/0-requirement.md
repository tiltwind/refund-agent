# 0 · 需求

RefundAgent 处理退款申请。系统结构见 [1 · 架构](https://tiltwind.github.io/refund-agent/doc/get-start/1-architecture.md)，设计取舍见 [2 · 设计](https://tiltwind.github.io/refund-agent/doc/get-start/2-design.md)，搭建步骤见 [3 · 实现](https://tiltwind.github.io/refund-agent/doc/get-start/3-impl.md)。

## 一、处理范围

用户从 App、H5 或客服工作台提交退款申请。RefundAgent 负责：

1. 从自然语言中提取诉求；
2. 检索适用政策；
3. 调用规则引擎判定；
4. 执行退款，或记录拒绝结果并说明原因。

标准申请自动处理，高风险和边界申请携带上下文转人工。目标自动闭环率为 70% 以上。

## 二、处理流程

| 步骤 | 动作 | 约束 |
|---|---|---|
| 1 | 提取订单号 | 客户身份来自网关认证结果，不从对话提取 |
| 2 | 查询客户档案 | 获取会员等级、近 90 天退款次数 |
| 3 | 检索退款政策 | 答复只能引用检索到的条款 |
| 4 | 判定退款资格 | 规则引擎的结果是唯一依据 |
| 5 | 执行终局动作 | 批准和拒绝都要落库，取得单号后再答复 |

模型只负责理解诉求和组织答复，不决定处理流程和退款结果。

## 三、判定规则

规则由规则服务实现。

| 规则 | 内容 | 优先级 |
|---|---|---|
| 订单有效性 | 订单存在、未退款、属于当前客户 | 最高 |
| 风控 | 近 90 天退款超过 3 次，转人工 | 高于会员权益 |
| 类目黑名单 | 生鲜、定制、虚拟商品不退 | — |
| 退货窗口 | 无理由：普通会员 7 天、金牌会员 15 天；质量问题 15 天 | — |
| 商品状态 | 无理由退货要求未拆封；质量问题不受此限 | — |

## 四、政策范围

政策库分两层：

- 法律法规（L01–L05）：确定法定底线；
- 平台政策（P01–P11）：平台与消费者的约定，也是答复的主要引用来源。

平台政策不得低于法定标准。平台承诺高于法定标准时，以平台承诺为准；平台文件互相冲突时，以 P02 为准。文档清单和元数据见 [政策文档库说明](https://tiltwind.github.io/refund-agent/doc/policy/README.md)。

## 五、验收标准

| 项 | 要求 |
|---|---|
| 身份 | 只操作当前认证客户的订单 |
| 判定 | 结果与规则引擎一致 |
| 落库 | 批准或拒绝均已落库，答复包含单号 |
| 引用 | 只引用检索到的政策条款 |
| 审计 | 流水包含 `actor` 和 `request_id` |
| 幂等 | 同一 `request_id` 重试不重复打款 |

单号用于约束“答复”和“执行”的一致性：没有完成终局动作，就拿不到可写入答复的单号。
