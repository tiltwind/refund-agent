# 数据集 r1 —— 检索评测样本集

96 条样本，四个字段。直接喂 `search_policy`，不经过 Agent，测的是[六步检索链路](https://github.com/tiltwind/refund-agent/blob/main/rag/retrieving/milvus.py)本身。

```bash
python rag/evals/generate_cases.py       # 重新生成（抽样稳定，措辞可能有细微出入）
python rag/evals/validate_cases.py       # 自检五项，不调模型
python rag/evals/push_dataset.py         # 推成 Langfuse 数据集 retrieval-cases-r1
```

设计口径与两个指标的算法见 [4 · 检索评测数据集](https://tiltwind.github.io/refund-agent/doc/get-start/4-rag-dataset.md)，
跑批与结果见 [5 · 检索评测](https://tiltwind.github.io/refund-agent/doc/get-start/5-rag-eval.md)。

## 一、样本格式

每行一个 JSON 对象。注释是说明，实际文件里没有。

```jsonc
{
  "case_id": "R1-081",
  "question": "商品已拆封但未实际使用，是否支持无理由退货？若支持，寄回运费由谁承担？",
  "ground_truth": "已拆封但未实际使用的商品不支持无理由退货，平台仅接受未拆封商品的无理由退货。若符合无理由退货条件，寄回运费由消费者承担，可自行选择快递或使用平台上门取件服务（费用从退款中扣除）。",
  "source": ["P05#002:00", "P06#001:00"]   // 出题的条文，排序指标的真值
}
```

| 字段 | 谁读它 |
|---|---|
| `question` | 跑批时直接喂 `search_policy` |
| `ground_truth` | Context Recall：按句拆开逐句判有没有被检回的上下文支撑 |
| `source` | 三个排序指标（`candidate_hit`、`hit@1` / `hit@4`、`mrr`）的真值；报告按文档分档也读它 |

Context Precision 不读任何字段 —— 它只看问题和检回的内容。排序指标反过来，只读 `source`：
判的是出题的那段条文在候选与证据列表里排第几，不调模型。

`ground_truth` 有一条硬要求：**一句只说一件事，且不以独立结论句开头**。「可以退。」这样的
句子切出来是一个不含条件、期限、数字的判定单元，检回的条款再对也支撑不了它，判负会记在
检索头上。自检里有这一条。

## 二、分布

| 切面 | 分布 |
|---|---|
| 类型 | 单块 82 条 · 跨块 14 条 |
| 出处 | 23 个文档档位，16 篇每篇 ≥ 4 条 |
| 种子块 | 去重后 52 个，占库里 353 个块的 15% |
| `ground_truth` 句数 | 1 句 46 条 · 2 句 46 条 · 3 句以上 4 条，均值 1.58 |
| `question` 长度 | 平均 35 字 |

一段条文出两条样本，问法各一档（书面 / 口语）。两档不落盘、也不分档报指标 —— 它们只是让
同一条规则被问到两次，一次给 BM25 送精确 term，一次压稠密一路和改写环节。

按 `case_id` 奇偶还原（奇数书面、偶数口语）后，两档的差距比任何两篇文档之间的差距都大：
Hit@4 是 0.917 对 0.688。下一版要把档位落成字段，报告才分得出这一档。

名额分配是「每篇保底 2 个种子块，块数 ≥ 20 的文档加 1 个」，不按块数比例分。P02 只有 10 个块
却是判定核心，L02 有 41 个块，按比例分会让数据集复现线上的命中分布 —— 而它的作用是暴露问题。
层内保证表格块与短块各有一个：表格是原子块，短块在 BM25 里天然吃亏，两类的检索行为都与
普通正文块不同。

跨块的 14 条来自 7 组指定的文档对，两段条文一起喂给生成器，标准答案两段都要用上。它压的是
Context Recall —— 只召回一半，答案里有一半的句子归因不到上下文，分数掉到 0.5。

## 三、这一版绑定了什么

`source` 里的 `chunk_id` 由切片位置派生（`{doc_id}#{parent_seq:03d}:{chunk_index:02d}`），
不是内容哈希。下面任何一项变了，样本都可能**静默失效** —— 用例照跑，只是分数暴跌，
看上去像检索退化。

| 绑定项 | 当前值 | 变更后 |
|---|---|---|
| 政策语料 | `doc/policy/` @ `fc6ef3b`（16 篇 / 353 个子块） | 增删小节会让该文档后续所有 ID 偏移，重新生成受影响文档的样本 |
| 切片参数 | `320 / 512 / overlap=0`（`rag/chunking/policy.py`） | 参数变了整个数据集作废，开 r2 |
| collection | `refund_policy_chunks` | 重新灌库后先跑自检 |
| 嵌入模型 | `BAAI/bge-m3`，`max_length=1024` | 换模型等于换向量空间，基线要重跑 |
| 生成模型 | `deepseek-v4-flash`，温度 0 | 只影响新增样本的措辞，已有样本不动 |
| 抽样种子 | `SEED = 20260817` | 改它等于换一批种子块，全集要重抽检 |

**什么时候开 r2**：切片参数变更、语料大改版、`ground_truth` 的写法口径变更。只是补样本就直接
往 `cases.jsonl` 里加 —— 版本号保持粗粒度，纵向对比才有连续的基线。

## 四、自检与抽检

[`validate_cases.py`](https://github.com/tiltwind/refund-agent/blob/main/rag/evals/validate_cases.py)
五项，不调模型：

| 检查 | 抓什么 |
|---|---|
| 四个字段齐全、`case_id` 唯一 | 跑批跑到一半才发现要重来 |
| `question` 不重复 | 同一个问题被重复计权 |
| `source` 里的 chunk_id 在库里存在 | 切片版本漂了 |
| `ground_truth` 里的数字在源块正文里出现过 | 凭空出现的天数、次数、金额是模型幻觉 |
| `ground_truth` 不以独立结论句开头 | 见第一节 |

当前全集零错误。

自检判不了「真人会不会这么问」。抽 10% 人工过一遍，判两件事：这个问题真人会不会这么问；
标准答案有没有超出源块 —— 超出的部分要么删，要么把那个块也加进 `source`。

## 五、已知偏差

| 偏差 | 影响 | 怎么处理 |
|---|---|---|
| `ground_truth` 平均只有 1.58 句 | 一句的那 46 条 Context Recall 非 0 即 1，单条读不出程度 | 看均值，不看单条 |
| `question` 与 `ground_truth` 出自同一个种子块 | 那个块进了上下文，Context Recall 就必然满分 —— 实测非空的 91 条里 88 条是 1.0，指标已经饱和 | 调参看排序指标；下一版把标准答案改成 3~5 个原子信息点 |
| 标准答案由模型写 | 可能漏掉源块里的条件 | 人工抽检；数字幻觉已由自检拦住 |
| 平台层与法规层口径不一致时，答案跟着**源块**走 | 同一个问题的两条样本给出相反答案 | 见下 |
| 样本覆盖 52 / 353 个块 | 未被抽到的块从未被测过 | 分层保证了每篇文档、两种块类型都有样本，不等于全覆盖 |

第三行最典型的一组：「拆封查验后能否退货」，L03 第十九条说应当退货，P05 第二条说平台只受理
未拆封 —— R1-011 与 R1-045 因此给出相反的答案。这不是生成错误，是语料本身的层级差异。
判定口径也因此定成「只判上下文里有没有，不判答案对不对」（[4 · 1.3](https://tiltwind.github.io/refund-agent/doc/get-start/4-rag-dataset.md#13-context-recall-怎么算)）。
